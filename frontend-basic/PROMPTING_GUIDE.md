# Claude Code 효율적인 프롬프팅 가이드

개발자가 Claude Code에게 정확하고 효율적인 코드를 얻어내기 위한 프롬프팅 원칙 정리.

## 1. 목표 + 제약을 함께 제시

"~해줘" 대신 **무엇을, 왜, 어떤 제약 안에서** 원하는지 명시한다.

- 나쁨: "로그인 기능 추가해줘"
- 좋음: "로그인 기능을 추가해줘. JWT 기반이고, 기존 `authStore.ts`의 패턴을 따라야 해. 세션 만료는 서버에서 처리하니 프론트는 401만 감지하면 돼."

## 2. 구체적 파일/경로/함수명 언급

코드베이스를 탐색하는 시간을 줄여준다. `src/api/user.ts`의 `fetchUser` 같은 식으로 짚어주면 탐색 없이 바로 정확한 지점을 수정할 수 있다.

## 3. "찾아줘" vs "고쳐줘"를 구분

- **원인을 모를 때**: 증상만 주고 조사를 맡긴다. ("이 버튼 클릭 시 가끔 두 번 호출되는데 원인 찾아줘")
- **원인을 이미 알 때**: 지시를 구체적으로 준다. ("디바운스 로직이 빠져서 그래, `useDebounce` 훅 적용해줘")

과도하게 절차를 지시하면 오히려 얕은 결과가 나올 수 있다.

## 4. 완료 조건(Definition of Done)을 명시

- "타입 에러 없이"
- "기존 테스트 통과 유지"
- "이 컴포넌트는 건드리지 마"

이런 경계를 주면 스코프를 벗어난 리팩토링을 막을 수 있다.

## 5. 반복되는 취향은 CLAUDE.md에 기록

"주석 달지 마", "에러 핸들링은 최소화해" 같은 반복 지시는 프로젝트의 `CLAUDE.md`에 적어두면 매번 말할 필요가 없다. `/init` 명령으로 초기 생성 가능.

## 6. 작업 단위를 적절히 쪼개기

너무 큰 요청("전체 앱 리팩토링해줘")보다 검증 가능한 단위로 나누면 정확도가 올라간다. 큰 작업이면 먼저 Plan 모드로 설계를 맞추고 진행하는 것이 좋다.

## 7. 피드백은 그때그때, 이유와 함께

"이렇게 하지 마"보다 "이렇게 하지 마, 왜냐하면 ~" 형태로 주면 이유를 기억하고 유사 상황에 일반화해서 적용할 수 있다.
